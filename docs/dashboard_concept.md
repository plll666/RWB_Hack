# Концепция дашборда: продажи и исполнение заказа

**Аудитория:** руководитель операций и категорийные менеджеры. Панель помогает находить изменения в продажах, видеть узкие места доставки и решать, какие категории или продавцы требуют внимания. Данные текущей версии ограничены историей выгрузки; причинность по этим показателям не утверждается.

Период выбирается по дате оформления заказа. Показатели выручки включают только `delivered`; счётчик оформленных заказов включает все статусы. Товарная выручка — `sum(item_price)`, без доставки. Для всех показателей ниже строки сначала сводятся к указанной базовой гранулярности.

| Показатель | Формула | Базовая гранулярность и источник | Ограничения / решение |
|---|---|---|---|
| Число заказов | Число заказов по статусу на месяц оформления | Один `core.orders.order_id` | Аддитивно по месяцам; показывает объём входящего потока |
| Товарная выручка | Сумма `item_price` доставленных позиций | `core.order_item` → месяц/категория/продавец через order_id | Аддитивна по непересекающимся позициям; использовать для динамики продаж |
| Средний чек | Среднее по заказам от суммы `item_price + freight_value` | Сначала один итог на `core.orders.order_id`, затем среднее | Неаддитивен; пересчитывать из заказов, использовать для оценки корзины |
| Доля статусов | Число заказов статуса / все заказы когорты оформления | Один `core.orders.order_id` | Неаддитивна; сверять структуру потока и всплески отмен/недоступности |
| Передача перевозчику | `handed_to_carrier_at - purchased_at` | Один заказ с обеими датами | Показывать медиану и 90-й перцентиль; отрицательные интервалы выделять отдельно, не исправлять |
| Срок доставки | `delivered_at - handed_to_carrier_at` | Один доставленный заказ с обеими датами | Показывать медиану/90-й перцентиль; пропуски и отрицательные интервалы — отдельные счётчики |
| Доставка в срок | Доставленные заказы, вручённые не позже обещанной календарной даты / доставленные с обеими датами | Один заказ с `delivered_at` и `estimated_delivery_at` | Не складывать доли; сравнивать календарные даты, а не timestamp с полуночью. Помогает найти зоны/периоды с ухудшением доставки |
| Повторные покупатели | Покупатели с >1 заказом / все покупатели выбранной когорты | Сначала заказы на `buyer_id` (`customer_unique_id`) | Неаддитивна; пересчитывать числитель и знаменатель. Использовать для оценки возврата покупателей |

**Срезы:** месяц оформления, статус, категория, продавец, штат продавца. Если добавлять географию покупателя, явно показывать, что один постоянный покупатель может иметь несколько адресных `customer_id`.

**Правила качества:** пустые даты доставки не входят в знаменатель временных метрик, их количество показывается рядом. Отрицательные интервалы сохраняются и маркируются. Месяцы без заказов остаются в календаре с нулевыми значениями. Выручка по категориям и продавцам считается из фактов core; платежи не присоединяются к позициям напрямую.
