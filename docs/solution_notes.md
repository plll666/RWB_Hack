# Короткая записка о решениях

Собрали типизированную модель `core` поверх неизменяемого `raw`: постоянный покупатель отделён от адресной записи, а заказ, позиция, платеж и отзыв хранятся на собственных уровнях детализации. Для позиций и платежей используются составные ключи, для отзывов — технический ключ, поскольку исходный `review_id` повторяется. Денежные значения хранятся в `numeric`, пустые даты остаются `NULL`.

Выручка для вопросов кейса — цена товаров доставленных заказов без доставки; средний чек считается по сумме товара и доставки внутри заказа. Пустая категория выделена отдельно, непереведённые категории не сливаются. Мы не меняли raw, не удаляли отзывы или аномальные заказы, не соединяли позиции с платежами напрямую и не исправляли даты без бизнес-правила. Такая структура сохраняет гранулярность и позволяет добавить новые срезы и вопросы без пересборки модели под каждый отчёт.
