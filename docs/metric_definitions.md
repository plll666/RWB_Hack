# Определения метрик блока Б

Все даты и адреса относятся к версии, действовавшей на момент заказа. Запросы читают `core`/`mart`; слой `raw` не изменяется.

| Вопрос | Гранулярность и определение |
|---|---|
| 6. История цены | Среди позиций доставленных заказов найти `product_id` с максимумом `count(distinct item_price)`. При равенстве выбрать меньший `product_id`. Затем сгруппировать позиции этого товара по дате оформления и цене; `count(*)` — число проданных единиц (в источнике отдельного количества нет). |
| 7. Доставка по штату | Одна доставленная запись заказа с заполненными `purchased_at`, `delivered_at`, `estimated_delivery_at`. Дни — точная разница timestamp в сутках. Опоздание — `delivered_at::date > estimated_delivery_at::date`. Группировка по историческому штату заказа; оставить группы с `count(*) >= 500`. Всегда показывать знаменатель. |
| 8. Статусы | Одна строка на заказ. Доля статуса считается от общего числа заказов. Число заказов без позиций считается через отдельный агрегат или `NOT EXISTS`, не через размножающий соединение с позициями. |
| 9. Платежи | Одна строка `order_payment` — один платёж. По штатам брать заказы с датой оформления в `[2018-01-01, 2019-01-01)` и исторический штат; вывести число, сумму `payment_value` и среднее `installments`. По типу оплаты — отдельная группировка по всей выгрузке. |
| 10. Оценка и доставка | Сначала уникальные пары `(order_id, review_score)`, затем только доставленные заказы с полным набором дат. Использовать формулы дней и опоздания из вопроса 7. Доля опозданий имеет знаменатель `reviewed_orders` в строке оценки. Это описательная ассоциация, не причинный вывод. |

Отрицательные интервалы не исключаются скрыто. Они диагностируются предупреждением; если для метрики выбран вариант исключения, его нужно назвать и отдельно посчитать.
