# Как запустить и использовать дашборд

> Стек — **FastAPI (бэкенд) + React/Vite (фронтенд)**. Решение команды изменило
> зафиксированный в `final_work_distribution.md` выбор Streamlit; прежняя
> Streamlit-версия (`dashboard/`) остаётся на диске как резерв для защиты,
> но не поддерживается. Команду запуска для корневого README передать
> участнику 2.

## 1. Что нужно

- **Python 3.10+** с пакетами бэкенда:

  ```bash
  pip install -r backend/requirements.txt
  ```

- **Node.js 18+** — для фронтенда (первый раз):

  ```bash
  cd frontend
  npm install
  ```

- Запущенная и собранная база проекта (Docker + PostgreSQL 16).
  Полная последовательность — в корневом `README.md`:

  ```bash
  bash scripts/setup.sh
  docker exec -i hack_postgres psql -U hack -d marketplace -v ON_ERROR_STOP=1 -f - < model/build.sql
  docker exec -i hack_postgres psql -U hack -d marketplace -v ON_ERROR_STOP=1 -f - < model/mart.sql
  ```

  Без `model/mart.sql` API не начнёт работу: запросы идут только к
  `core` и `mart`.

## 2. Подключение к БД

Бэкенд читает `DATABASE_URL`; если переменная не задана, пробует локальную
учебную базу из README на порту **5433**, затем 5432:

```bash
# пример для нестандартного порта/пароля
export DATABASE_URL=postgresql://hack:hack@localhost:5433/marketplace
```

Секреты в репозиторий не коммитятся. Проверка соединения:

```bash
curl http://localhost:8000/api/health   # {"ok":true, ...} — адрес БД в ответе
```

## 3. Запуск (два процесса)

Из корня репозитория — бэкенд:

```bash
uvicorn backend.main:app --port 8000
```

И фронтенд (второй терминал):

```bash
cd frontend
npm run dev
```

Открыть в браузере адрес, который напечатает Vite: `http://localhost:5174/`
(если 5173 свободен — там). В dev-режиме Vite проксирует `/api` на `:8000`,
поэтому фронтенду не важен адрес бэкенда вручную. Для собранной версии:
`npm run build` и `npm run preview` (порт 4173, CORS на бэкенде уже открыт).

## 4. Эндпоинты API (для проверки рукам, без UI)

| Запрос | Возвращает |
|---|---|
| `GET /api/health` | доступность БД |
| `GET /api/meta` | границы снимка, список штатов |
| `GET /api/overview?date_from=&date_to=&states=SP` | KPI, месяцы, статусы |
| `GET /api/delivery?...&min_orders=500` | сроки, штаты с порогом, оценки |
| `GET /api/categories?...&category_ids=&seller_id=` | категории/продавцы |
| `GET /api/product/{product_id}` | карточка и история цен (вопрос 6) |
| `GET /api/product/champion` | чемпион по числу разных цен |
| `GET /api/quality` | диагностика качества |

Все параметры передаются в SQL только через `%s`-плейсхолдеры; ошибка БД
возвращает HTTP 503 с текстом и инструкцией сборки, не пустую диаграмму.

## 5. Сценарий использования (демо на защите, ≤ 2 минут)

1. Открыть вкладку **Обзор**: KPI (заказы, выручка по доставленным,
   средний чек, доля «в срок» с знаменателем), помесячная динамика,
   статусы заказов.
2. Сузить **период** и выбрать **штаты** (например, `SP`), затем вкладка
   **Доставка**: среднее/медиана, доля опозданий, таблица штатов
   (порог ≥ 500 заказов, число можно менять), связь оценки и срока.
3. Перейти в **Категории и продавцы**: локальные фильтры категории и
   продавца (ID вставляется в поле), таблицы с **копируемыми**
   `product_id`/`seller_id`; в «История цен товара» по умолчанию открыт
   чемпион вопроса 6 — товара с наибольшим числом разных цен.
4. В **Качество данных** — период снимка, счётчики справочников,
   пропуски и расхождения (совпадают с `model/checks.sql`).

## 6. Поведение и ограничения

- Пустой срез: явное «Нет данных», нулевых графиков выручки нет.
- Метрики доставки всегда показывают знаменатель — доставленные заказы
  с полным набором дат (purchase / estimated / delivered).
- Локальные фильтры категории/продавца действуют только на свою вкладку.
- Ошибки БД/модели показываются баннером с инструкцией запуска
  (`README`: build → mart → uvicorn), ошибки SQL не маскируются.
- Данные исторические, до октября 2018 (последний месяц снимка
  частичный); тег «Исторические данные до 17.10.2018» — в шапке.
- Тёмная/светлая темы переключаются в шапке, выбор запоминается.
